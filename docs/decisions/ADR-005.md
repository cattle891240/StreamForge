# ADR-005: 部署目标 macOS 13.0 与 UI 状态管理方案

## Status

Accepted（2026-09-28）

## Background

需求要求 macOS 原生 GUI，未指定最低系统版本。两个技术现实决定了选择空间：

1. Swift 的 **Observation 框架 / `@Observable` 宏要求 macOS 14.0+**，
   而 SwiftUI 的传统方案 `ObservableObject` + `@Published` 自 macOS 10.15 起可用。
2. SwiftUI 近两个大版本新增了不少便捷 API（`.inspector`、`ContentUnavailableView`、
   `@Observable`、部分 `Table` 修饰符等），若把部署目标定到 14/15 会显著好写，
   但会排除相当一部分仍在使用 Ventura 的 Mac。

同时本机实测：`swiftc -target x86_64-apple-macosx13.0 -sdk MacOSX15.5.sdk` 编译一个含
`@main` + `WindowGroup` + `Settings` + `Image(systemName:)` 的 SwiftUI App **通过**（约 20 s），
证明"SDK 15.5 + 部署目标 13.0"这一组合可行。

## Decision

**部署目标 = macOS 13.0（Ventura）**，并据此锁定 UI 层技术约束：

1. **状态管理禁用 `@Observable` / Observation 框架**（要求 macOS 14）。
   统一使用 `ObservableObject` + `@Published`，配合 `@StateObject` / `@EnvironmentObject` / `@ObservedObject`。
2. **语言模式 `-swift-version 5`**（ADR-001），并发安全靠
   "业务层跑自己的串行 `DispatchQueue`" + "所有 `@Published` 变更只发生在 MainActor" 保证，
   不依赖 Swift 6 的编译期隔离检查。
3. **只允许 macOS 13 可用的 SwiftUI API**。禁用清单（非穷尽，发现即改）：
   `.inspector`、`ContentUnavailableView`、`@Observable`、`NavigationSplitView` 的 macOS 14+ 变体、
   `.scrollBounceBehavior`、`.onChange(of:initial:_)` 的双参数新签名。
   可用：`NavigationSplitView`、`Table`、`Form` + `.formStyle(.grouped)`、`Settings` scene、
   `.onDrop`、`.preferredColorScheme`、`Commands`、`LazyVStack`。
4. **深色模式**：不硬编码任何颜色。语义色（`green/orange/red/secondary`）+ `Color.accentColor`，
   由系统自动适配；`Info.plist` 设 `NSRequiresAquaSystemAppearance=false`。
   设置项提供"跟随系统 / 浅色 / 深色"覆盖（`.preferredColorScheme`）。
   **禁止紫→粉渐变**（专家团 P0-2）。
5. **图标一律 SF Symbols**，名称集中在 `UI/SFSymbols.swift`，**禁止 emoji 作功能图标**（专家团 P0-1）。
   App 图标例外：由 `Scripts/make-icon.swift` 用 CoreGraphics 路径绘制，
   不使用 SF Symbols（SF Symbols 许可不允许用作 App Icon）。

## Consequences

**正面**

- 覆盖面更大（Ventura 及以后），且已实测可编译。
- `ObservableObject` 是久经验证的模型，Swift 6.1.2 在 Swift 5 语言模式下无并发检查噪声。
- 语义色让深色模式几乎零成本。

**负面**

- 写起来略啰嗦（`@Published` 比 `@Observable` 需要更多样板），会与"单文件 ≤300 行"门禁打架——
  缓解：视图按组件拆分，状态对象按职责拆分（TaskQueue / AppSettings 各自独立）。
- 需要人工维护"macOS 14+ API 禁用清单"；CI 因编译带 `-target ...13.0`，
  **编译器会自动拦截**绝大多数违规（可用性错误），这是主要防线。
- 若未来发现某个必需 API 只在 14+ 提供，需回来修订本 ADR 并把部署目标提到 14.0
  （届时需同步改 README、Info.plist 的 `LSMinimumSystemVersion`）。
