# ADR-001: 不使用 SwiftPM，改用 swiftc 直接编译的脚本化构建

## Status

Accepted（2026-09-28）

## Background

本机开发环境只有 Xcode Command Line Tools，无完整 Xcode。实测两个阻断性事实：

1. **SwiftPM 不可用**：`swift build` 崩溃，报 dyld 符号缺失
   （`Symbol not found: _$s7llbuild15ExternalCommandPAAE19depedencyDataFormat...`）。
   工具链与 CLT 自带的 llbuild 版本不匹配，且无法通过重装 CLT 稳妥修复。
   连带后果：`swift test` 也不可用（见 ADR-006）。
2. **默认 SDK 与编译器不兼容**：`xcrun --sdk macosx --show-sdk-version` 返回 26.2，
   而 Swift 6.1.2 用该 SDK 编译 SwiftUI 代码时报
   `cannot suppress '~Copyable' on generic parameter`。可用的是
   `/Library/Developer/CommandLineTools/SDKs/MacOSX15.5.sdk`。
   陷阱：`MacOSX.sdk` 是指向 15.5 的 symlink，但 `xcrun` 报告 26.2，二者不一致。

同时，项目**零第三方依赖**（ADR-002 同源原则），SwiftPM 的核心价值（依赖解析）本就用不上。

## Decision

构建方式 = **`swiftc` 一次性编译全部源文件 + shell 脚本编排**，不使用 `Package.swift`。

具体约束：

- **不引入 `Package.swift`**。若未来有人添加，视为违反本决策（CI 门禁 `check-layout.sh` 检查其不存在）。
- 编译标志固定：
  ```
  swiftc -O -parse-as-library -swift-version 5 \
         -target <arch>-apple-macosx13.0 \
         -sdk <探测所得 SDK> \
         <全部 Sources/**/*.swift> -o .build/<config>/StreamForge
  ```
  - `-parse-as-library` 必须（否则 `@main` 与顶层代码冲突）。
  - `-swift-version 5` 必须：Swift 6 严格并发检查在 MVP 阶段会制造大量 Sendable/actor
    隔离噪声；并发安全改用串行队列 + 显式 `@MainActor` 保证。
  - 只用 `-target`，不用 `-macosx-version-min`（两者冲突）。
- **SDK 探测策略**（`Scripts/find-sdk.sh`）：按优先级尝试
  `$MACOSX_SDK` → `15.5` → `15.4` → `15.2` → `14.5`（在 CLT SDKs 目录与 Xcode SDKs 目录分别查找）
  → 最后兜底 `xcrun --sdk macosx --show-sdk-path`。
  每个候选都跑一次**真实编译探针**（`Scripts/sdk-probe.swift`，含 SwiftUI + `@main` + `WindowGroup`
  + `Settings` + `ObservableObject`），第一个编译通过的即采用，结果缓存到 `.build/.sdk-cache`。
  探针必须包含 SwiftUI 真实用法——26.2 的不兼容只在 SwiftUI 泛型展开时才暴露，
  只编译 `print("hi")` 的探针会误判通过。
- 源文件列表用 `find ... | sort` 生成，保证可复现。
- 打包由 `Scripts/package.sh` 手工组装 `.app`（Info.plist / MacOS / Resources）并 `hdiutil` 出 dmg，
  由 `Scripts/make-icon.swift`（CoreGraphics）生成图标。

## Consequences

**正面**

- 绕开 SwiftPM 崩溃，本机与 CI 都能构建。
- 构建链路 100% 可见、可调；SDK/架构/部署目标全部显式，不依赖 `xcrun` 的隐式选择。
- CI（完整 Xcode）与本机（CLT）用同一份脚本，靠探测逻辑自适应，无需维护两套。

**负面**

- 无增量编译：全量编译随文件增长。当前规模实测约 20 s（单文件探针），
  全项目预计 30–60 s，可接受；CI 缓存 `.build` 缓解。
- 资源（.icns、Info.plist 模板）需脚本手工组装，不能享用 Xcode 的 asset catalog 编译。
- 新增文件无需在 manifest 声明——这既是便利也是风险：`find` 会自动纳入，
  因此必须靠 `check-layout.sh` 的门禁（行数/依赖方向）补上约束。
- 无法使用 Xcode 的可视化调试与 Instruments 界面（仍可用命令行 Instruments/Instruments 模板）。
