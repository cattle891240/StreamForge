# ADR-006: 自写轻量测试 harness 替代 XCTest

## Status

Accepted（2026-09-28）

## Background

两个实测阻断：

1. **Command Line Tools 的 SDK 中不存在 `XCTest.framework`**，无法编译 XCTest target。
2. **SwiftPM 崩溃**（ADR-001），连带 `swift test` 不可用。

因此"测试"必须自建，且不能依赖任何需要 SwiftPM 或 XCTest 的机制。
同时，本项目的核心风险集中在**纯逻辑**：输出解析（ADR-004）、参数构建、暂停策略、格式化、环形缓冲。
这些逻辑天然可测，不需要 UI 自动化。

## Decision

**测试 = 一个普通可执行文件 + 自写断言库 + 退出码。**

### 编译范围（重点）

`Scripts/test.sh` 编译时**排除** `Sources/StreamForge/App` 与 `Sources/StreamForge/UI`：

```bash
SRCS=$(find Sources -name '*.swift' -not -path '*/UI/*' -not -path '*/App/*' | sort)
TESTS=$(find Tests -name '*.swift' | sort)
swiftc "${COMMON[@]}" $SRCS $TESTS -o .build/test/StreamForgeTests
.build/test/StreamForgeTests "$@"
```

这带来一条**架构级收益**：UI 与 App 层如果不小心混入业务逻辑，就无法被编译进测试，
问题会在 CI 第一时间暴露——这比任何文档约定都有效。

### Harness API（`Tests/Harness/MiniTest.swift`，≤180 行）

```swift
public func suite(_ name: String, _ body: () -> Void)
public func test(_ name: String, _ body: @escaping () throws -> Void)
public func expectEqual<T: Equatable>(_ actual: T, _ expected: T, _ hint: String = "", file: StaticString = #file, line: UInt = #line)
public func expectTrue / expectFalse / expectNil / expectNotNil / expectContains
public func expectThrows<E: Error>(_ expected: E.Type, _ body: () throws -> Void, ...)
```

输出：`PASS <suite>/<name>` / `FAIL <suite>/<name>` + 失败处的文件行列与期望/实际值，
末尾汇总 `N passed, M failed`，**退出码 0/1**。支持 `--filter <关键字>` 与 `--list`。

### 注册机制

Swift 无 XCTest 的运行时发现能力，`Tests/Harness/main.swift` **显式注册**各测试文件：

```swift
registerParserTests(); registerSplitterTests(); registerArgumentBuilderTests()
registerPauseControllerTests(); registerDependencyProbeTests()
registerFormatterTests(); registerRingBufferTests()
exit(TestRunner.shared.run(filter: CommandLine.arguments.dropFirst().first) ? 0 : 1)
```

**纪律**：新增 `XxxTests.swift` 必须同时在此注册，否则永不执行——PR 复核必查项。

### 覆盖要求（对齐「生成式代码失效模式」）

| 失效模式 | 定向用例 |
|---|---|
| Happy-path 偏差 | 每个解析器都有"空输入 / 半行 / 只有进度无日志 / 只有日志无进度" |
| 沉默逻辑错误 | 粘连切分断言日志条数 == 时间戳数；**变异加固**：改坏 lookahead 正则后必须有测试变红 |
| 幻觉依赖/接口 | `PauseControllerTests` 用 `ProcessControlling` 协议替身，不真起进程 |
| 边界 | `-0.00Bps`、`-0.00%`、`--:--:--`、`(1)` 重试计数、字节字段缺失、空字符串选项 |
| UTF-8 | 3 字节 `━` 跨 chunk 截断 |
| 并发 | `TaskQueue` 并发上限生效（并发 2 时第三个任务排队） |

### 集成测试

真起进程的用例（进程组 SIGSTOP、依赖探测）标记 `--include-integration`，
**CI 默认不跑**，本地开发按需运行，避免污染 CI 稳定性。

### Fixtures

`Tests/Fixtures/*.txt` 为真实/近真实内核输出（含本次实测抓取的
`kernel_progress_glued.txt` 与 `kernel_stderr_stacktrace.txt`）。
测试只读文件，**不依赖网络、不依赖内核是否已安装**。

## Consequences

**正面**

- 绕开 XCTest 缺失与 SwiftPM 崩溃，CI 与本机同一套命令。
- 测试可执行文件与产物用同一编译器、同一 SDK、同一部署目标，不会出现"测试环境与构建环境不一致"。
- 排除 UI 的编译范围本身就是一条可执行的架构门禁。
- 无第三方依赖，符合零依赖原则。

**负面**

- 没有 XCTest 的 XCTAssert 语义细节、没有 Xcode 测试导航、没有覆盖率工具。
  缓解：断言库自建、失败输出带 `#file`/`#line`、覆盖率靠"用例清单 + 变异加固"人工保证。
- 显式注册是人工纪律，可能被遗忘。缓解：`main.swift` 顶部注释写明，
  并在 `Tests/Harness/MiniTest.swift` 提供一个 `expectTrue(registeredSuiteCount >= 7)` 的自检用例。
- 无法做 SwiftUI 视图快照测试——MVP 接受，UI 靠人工冒烟（architecture.md §10 端到端验证）。
