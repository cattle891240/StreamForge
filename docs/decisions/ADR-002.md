# ADR-002: 不捆绑上游二进制，只做外部依赖检测与引导

## Status

Accepted（2026-09-28）

## Background

StreamForge 是 N_m3u8DL-RE（MIT，作者 nilaoda）的 GUI 封装。产品需求要求"自动检测并引导配置
外部依赖（下载器本体、ffmpeg），缺失时给出清晰提示与修复指引"——这本身已隐含"外部"。
需要明确的决策是：**是否在发布包内捆绑一份 N_m3u8DL-RE / ffmpeg 二进制**。

考察的事实：

- N_m3u8DL-RE 是 .NET（C#）程序，官方按平台发布独立包：
  `N_m3u8DL-RE_v0.6.0-beta_osx-arm64_20260629.tar.gz`（约数十 MB）、`_osx-x64_`。
  ffmpeg 的静态构建同样体积可观。
- 发布产物未经 Developer ID 签名与公证（无开发者账号）。未签名的 bundle 内嵌第三方可执行文件时，
  Gatekeeper 会对**整个 bundle** 判定更严，且内嵌二进制各自带 quarantine 属性时会直接无法执行。
- 上游是 Beta，迭代频繁（本机实测版本 20260628，与半年前的构建差异明显）。
  捆绑等于把版本升级责任转移到我们：用户拿到的 GUI 会长期带着一个过期内核。
- MIT 许可允许再分发，但要求**保留版权声明与许可全文**；ffmpeg 若选择 GPL 构建则分发义务显著更重
  （LGPL/GPL 的源码提供义务），选错构建版本会引入合规风险。

## Decision

**不捆绑任何上游二进制。** StreamForge 只做：

1. 检测：启动时 + 设置页手动触发，按候选路径搜索并做"可执行 / 能跑 / 未被隔离"三步校验
   （详见 architecture.md §6）。
2. 引导：针对 `notFound / notExecutable / quarantined / archMismatch / unverified(version)` 五种状态
   渲染可一键复制的修复命令（含 `xattr -dr com.apple.quarantine`）。
3. 记录：用户指定的路径写入设置，下次直接复用。

合规落地：

- `LICENSE` 采用 **MIT，与上游一致**，并在 `NOTICE.md` 完整保留上游版权声明与 MIT 全文引用，
  明确"StreamForge 不包含、不修改、不分发 N_m3u8DL-RE 本体"。
- README 声明：ffmpeg 请用户自行安装（`brew install ffmpeg`），本项目不分发任何 GPL/LGPL 二进制。
- README 声明工具用途：仅用于下载用户拥有合法权利的内容。

## Consequences

**正面**

- 发布包体积极小（仅 App 自身，数百 KB 级），dmg 构建快。
- 上游升级由用户自己完成，我们永不"锁死"内核版本；版本校验只做软提示（低于 0.6.0 标记 unverified）。
- 规避 GPL/LGPL 分发义务与 Gatekeeper 对内嵌未签名二进制的额外拦截。
- 不需要处理 universal binary（arm64/x64 两版内核）的打包与选择逻辑。

**负面**

- 首次使用门槛：用户必须先装内核与 ffmpeg，否则 App 完全不可用。
  缓解：启动横幅 + 逐状态复制命令 + README 顶部安装章节。
- 依赖路径/版本由环境决定，排障信息来自用户环境。缓解：任务详情保留完整命令行，日志面板原样呈现内核输出。
- 用户自行下载的内核常被 Gatekeeper 隔离（`com.apple.quarantine`），
  这是"看起来装了但跑不起来"的高频坑——必须作为一等公民写进引导文案（已列入检测项）。
